# 视觉工作台前端接口协作说明

## 1. 通用约定

Base URL：

```txt
http://localhost:3101/api/v1
```

统一响应：

```ts
interface ApiResponse<T> {
  code: number
  message: string
  data: T
  requestId: string
}
```

任务状态：

```ts
type TaskStatus = 'waiting' | 'queued' | 'generating' | 'success' | 'fail' | 'canceled'
```

所有图生图模块固定参数：

| 参数 | 值 |
| --- | --- |
| Kie model | `gpt-image-2-image-to-image` |
| aspect_ratio | `16:9` |
| resolution | `2K` |

结果图保存规则：

```txt
D:\usedCarPlatform\backend\storage\results\{moduleCode}\
```

结果图静态访问规则：

```txt
http://localhost:3101/results/{moduleCode}/{fileName}
```

## 2. 上传车辆图

```http
POST /api/v1/assets/upload
Content-Type: multipart/form-data
```

form-data：

| Key | Type | Value |
| --- | --- | --- |
| `purpose` | Text | `car_exterior` |
| `file` | File | JPG / PNG / WebP 车辆外观图 |

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "assetId": "asset_xxx",
    "purpose": "car_exterior",
    "url": "http://localhost:3101/uploads/upload_xxx.jpg",
    "fileName": "car.jpg",
    "mimeType": "image/jpeg",
    "size": 123456
  },
  "requestId": "req_xxx"
}
```

前端记录：

```txt
data.assetId
```

产品逻辑：

- 用户第一次上传 Logo：创建账号默认 Logo。
- 用户点击“重新上传”：调用同一个接口，替换账号默认 Logo。
- 用户开启“使用 Logo”：创建任务时传 `useLogo: true`，后端自动使用账号默认 Logo。
- 用户关闭“使用 Logo”：不传 `useLogo` 或传 `false`。

## 6. 创建图生图任务

接口路径按模块替换：

```http
POST /api/v1/modules/{moduleCode}/tasks
Content-Type: application/json
```

不使用 Logo：

```json
{
  "inputAssetId": "车辆图assetId",
  "optionId": "white-studio",
  "useLogo": false
}
```

使用账号默认 Logo：

```json
{
  "inputAssetId": "车辆图assetId",
  "optionId": "white-studio",
  "useLogo": true
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `inputAssetId` | string | 是 | 上传车辆图返回的 `assetId` |
| `optionId` | string | 否 | 场景选项 ID，不传或未知时使用模块默认场景 |
| `useLogo` | boolean | 否 | `true` 时使用账号默认 Logo |
| `logoAssetId` | string | 否 | 调试或特殊场景用；正常前端不需要传 |

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "taskId": "task_xxx",
    "moduleCode": "showroom-light",
    "status": "queued",
    "progress": 5,
    "kieTaskId": "kie_task_xxx",
    "optionId": "white-studio",
    "sceneTitle": "经典白棚",
    "sceneReferenceImageUrl": "https://...",
    "logoAssetId": "asset_logo_xxx",
    "inputImageCount": 3,
    "pollingUrl": "/api/v1/tasks/task_xxx",
    "createdAt": "2026-05-28T14:00:00.000Z"
  },
  "requestId": "req_xxx"
}
```

说明：

- `inputImageCount=2`：未使用 Logo。
- `inputImageCount=3`：使用 Logo。

### 8.4 轮询结果

```http
GET http://localhost:3101/api/v1/tasks/{taskId}
```

每 3-5 秒请求一次，直到：

```txt
data.status = success 或 fail
```

验收标准：

- 创建任务返回 HTTP 200。
- 最终 `data.outputRatio=16:9`。
- 最终 `data.resolution=2K`。
- 成功时 `data.resultImages[0].url` 可以访问。
- 成功时 `data.resultImages[0].localPath` 对应本地文件存在。

## 9. 前端接入要点

- 前端上传车辆图后，把 `assetId` 传给创建任务接口。
- 前端选择场景时，只传 `optionId`。
- 前端打开“使用 Logo”面板时，调用 `GET /api/v1/user/logo` 查询默认 Logo。
- 用户第一次上传 Logo 或点击“重新上传”时，调用 `POST /api/v1/user/logo`。
- 前端开启 Logo 时，创建任务传 `useLogo: true`。
- 前端关闭 Logo 时，不传 `useLogo` 或传 `false`。
- 前端不传 prompt。
- 前端不上传场景参考图；后端按 `moduleCode + optionId` 维护参考图。

## 10. 烤漆翻新模块

接口：

```http
POST /api/v1/modules/paint-refresh/tasks
Content-Type: application/json
```

请求体：

```json
{
  "inputAssetId": "车辆图assetId",
  "colorCode": "可选颜色预设"
}
```

字段说明：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `inputAssetId` | string | 是 | 上传车辆图返回的 `assetId` |
| `colorCode` | string | 否 | 前端未来颜色预设值；不传时只做清洁翻新，不换色 |

不传 `colorCode` 时，后端使用清洁翻新 prompt：

```txt
对整辆车进行全面清洁与精细化翻新处理，重点提升车身洁净度、漆面光泽感与整体高级质感。保留原车颜色、车型、结构和拍摄角度不变，清除车身表面的灰尘、污渍和暗沉感，使漆面更加明亮通透、有镜面反光效果；同时增强轮毂的金属质感与干净度，让整车呈现焕然一新、干净整洁的视觉效果。
```

传 `colorCode` 时，后端把 `{COLOR_CODE}` 替换为前端传入值：

```txt
对整辆车进行全面清洁与烤漆翻新处理，重点提升车身洁净度、漆面亮度与轮毂金属质感。在保留原车车型、结构和拍摄角度不变的前提下，将车身颜色更换为 {COLOR_CODE} 对应的颜色，并清除车身表面的灰尘、污渍和老旧感，使新车漆呈现均匀、细腻、明亮、有光泽的效果；同时让轮毂更加干净有金属光泽，整体画面体现出整车翻新后的高级感与焕新效果。
```

成功创建响应：
